# Astral aura store

The owner requested a $4.99 aura cosmetic and a visible store. This implementation uses direct USD purchases: a small catalog does not need a premium-currency wallet, conversion bundles or leftover balances. Earned auction/duel coins remain separate from all paid appearances. This is a product decision, not a claim of higher revenue.

Astral aura is a permanent account cosmetic priced at 499 USD cents by the server. Its violet halo and orbiting lights use the same lightweight Canvas function in the storefront preview and world renderer. Reduced motion uses a still halo. It adds no stats, combat procs, damage, healing, resource yield or trade value. Accounts can equip one aura alongside one nameplate. The additive SQLite aura-column migration retains existing names, character links and nameplate selections; repeated startup is safe.

The existing Stripe one-time checkout, signed payment fulfillment and refund/dispute revocation cover the new SKU. Ownership is required before selection. The authoritative server replicates the chosen aura; input packets cannot grant it. Refunding the aura removes its ownership/selection without removing a separately owned nameplate. Clearing appearances removes both visible selections, without deleting purchases. Aura entitlement is account data, not an item in a guest character save or a market listing.

Open `/?store=preview` or Store & account to see the collection without entering the world. The featured card shows the aura, $4.99 USD, one-time terms and actual checkout availability. Real-provider credentials and billing activation remain absent and on hold. Disabled demo checkout is intentional. Provider-configured test checkout is labeled test-only; real checkout will display applicable tax separately. No real charge, external product creation or merchant activation was performed.

Validation: 103 rules/storage tests and all disposable multiplayer/account/contract/economy/skills/equipment/duel/restart protocols passed locally. New coverage checks catalog pricing, ownership, independent aura/nameplate selection, refund revocation, unchanged stats/coins and legacy-account migration. The account WebSocket test checks aura/nameplate retention across crash and rejects forged aura input. Browser proof uses a seeded disposable account, with no real purchase or owner-character grants; the temporary test sign-in cookie is cleared afterward. Browser store animation stops on dialog close, and downloads remain within the existing asset budget. Exact public CI status is separate from local verification.
